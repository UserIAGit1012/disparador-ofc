# Document

Create or update documentation for the specified code or feature.

## Steps
1. **Read** the code and understand what it does
2. **Check** existing docs — update rather than duplicate
3. **Write** documentation that answers:
   - What does this do?
   - How do you use it?
   - What are the important parameters/options?
   - Are there gotchas or non-obvious behavior?
4. **Include** a usage example if the API isn't self-explanatory

## Rules
- Write for the reader, not the author
- Don't document the obvious — focus on the non-obvious
- Keep examples minimal and runnable
- Update existing docs rather than creating parallel docs
- If something is complex enough to need extensive docs, consider simplifying the code instead
